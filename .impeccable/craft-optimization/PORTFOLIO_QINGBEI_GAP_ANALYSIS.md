# 清北教学档案袋设计理念 × 现网差异分析

> 2026-07-16 · 联网公开材料 + 现网 `edu-quality` portfolio / mark-vue  
> **状态：用户认可清北理念 · 进入「须补充」规格**（只文档/看板，未改业务码）  
> 看板：`#qingbei-gap` · 关联：`PORTFOLIO_ENTRY_IA_08.md` · `docs/19-后端-edu-quality.md`

## 0. 一句话

| 主体 | 产品心智 |
|------|----------|
| **清华** | 人事/教务评价制度改革：**教学代表作** +「三个全」；服务**晋升全覆盖评袋**与青年教师成长 |
| **北大** | 教师教学发展中心：**发展与反思**优先；四维内容 + 系统汇数形成雏形；过程/展示/评估三类用途 |
| **本产品（nybc）** | 多租户 SaaS：**证据采集—审核—完整度—场景出包**（职称/双师/年审）+ 组织治理；与 **OBE 质量域**并列，不是校内单一「教发平台」 |

**差异主轴：** 清北偏「**叙事 + 数据 + 评袋/发展**」；现网偏「**材料证据流水线 + 完整度 KPI + 多场景合规**」。能力上可对齐，**产品语言与主路径心智尚未按清北「代表作/清单模块」组织**。

## 1. 清北设计理念（公开源）

### 1.1 清华大学

来源：[清华新闻 / 中国教育报转载](https://www.tsinghua.edu.cn/info/1182/108742.htm)、[教育部转载](http://www.moe.gov.cn/jyb_xwfb/moe_2082/2023/2023_zl25/202312/t20231215_1094692.html)、[曹建谈教学档案袋](http://www.moe.gov.cn/jyb_xwfb/moe_2082/2023/2023_zl25/202407/t20240709_1140340.html)

| 维度 | 理念要点 |
|------|----------|
| **制度目的** | 破「五唯」；把教书育人纳入学术评价；教学作为第一学术责任 |
| **产品隐喻** | 教学「简历/代表作」；不是材料堆砌；要凝练理念、风格、特色 |
| **清单结构** | **六大模块 18 条**：必选=教学简历、教学数据、教学陈述、教学过程记录；可选=教学发展与研究、教学成果与奖励 |
| **三个全** | 全过程记录（课前准备 / 过程 / 结果反馈）· 全要素评估（态度/投入/成效/评教等进晋升）· 全方位提升（内驱 + 院系反馈） |
| **纵横** | 纵向：课前→课中→课后；横向：反思差距、凝聚特色 |
| **评价用法** | **晋升全覆盖**；**院系教学委员会**对袋作基本评价；校级专家异议与抽查；不合格督促完善 |
| **质量观** | 数据翔实 + 材料完备 + **反思深入**；数据与理念/自评有机结合 |
| **人群** | 重点青年教师；沙龙培训指导「建立」；青年教学优秀奖试点用袋 |
| **反例** | 不是严管分出高下；不是千人一面；不是只看评教后 5% |

### 1.2 北京大学

来源：[北大教学档案袋平台](https://teaching.pku.edu.cn/dad/dzjxdad)、中心公开说明

| 维度 | 理念要点 |
|------|----------|
| **制度目的** | 促进教师**教学发展与反思**；评估证据 + 改进工具 |
| **档案观** | 非资料简单合集；有目标甄选组织以说明教学有效性 |
| **三类用途** | 过程性 / 展示性 / **评估性**（晋升或求职） |
| **材料三角** | ① 来自自己（理念、职责、大纲）② 来自他人（学评、同行、荣誉）③ 教学产出（学生作品等） |
| **四大维度** | 教学基本信息 · 教学成果 · 教学发展 · 教学评价 |
| **平台角色** | 汇聚教学数据与教发活动过程数据 → 快速形成袋的**雏形**；支撑发展项目设计与评价 |
| **社群** | 电子袋便于分享、阅读、评论，激发教学讨论（经典 ePortfolio） |

### 1.3 清北共识（可复用原则）

1. **教师主体**，持续建立与修订，而非一次性交材料。  
2. **客观数据 + 个人阐述/反思** 双轨，缺一不可。  
3. **用途分层**：日常过程记录 / 展示 / 评估（晋升）可共用底座、不同出口。  
4. **评袋权在院系学术/教学共同体**，平台是证据与组织工具。  
5. **反堆砌**：求精、叙事、成长轨迹，不是完整度刷满即优秀。

## 2. 现网产品画像（源码）

| 层 | 现网事实 |
|----|----------|
| 域 | `/portfolio/*` 教学档案袋；与 `/quality` OBE **并列**（见 KB §1） |
| 教师主链 | 工作台 → 认识档案 → 采集 → 我的档案 → 审核进度（`PORTFOLIO_TEACHER_JOURNEY`） |
| 内容页 | 个人资料 · **教学理念** · **课程档案（五框架）** · 获奖 · 拓展活动 · 分类填报 · 材料库/采集 |
| 场景 | 职称材料包 · 双师/资格 · 年度考核（**评估性出口强**） |
| 治理 | 模板发布 · 名册 · 院系审核台（**材料任务队列**）· 学校驾驶舱 · 完整度/缺口 · 导出审批 |
| 智能 | AI 六类任务、四助手、OCR/采集候选（偏**证据生产**） |
| 指标 | `completenessPercent`、五框架齐备、院系/全校快照 KPI |

## 3. 对照矩阵（理念 → 现网）

| 清北原则 | 现网对齐度 | 差异说明 |
|----------|:----------:|----------|
| 教师主体、建立自己的袋 | **高** | 普通人锁本人；onboarding/隐私/模板就绪=启用语义（见入口合同） |
| 数据 + 理念陈述双轨 | **中高** | 有 `philosophy`、课程档案、讲授课数据；**缺**「教学清单六模块」产品叙事与课前中后过程记录一等公民 |
| 教学代表作 / 凝练叙事 | **中低** | 主路径是待办+完整度+采集审核；**弱**「打磨代表作/版本叙事/退回重写」的晋升评议体验（清华案例） |
| 全过程记录（课前/中/后） | **低–中** | 课程档案/材料偏静态证据；**弱**周课反思、课堂过程连续记录产品环 |
| 全要素进晋升评估 | **中高** | 职称场景+条件模板+证据绑定强；形态是**条件核验+材料包**，不是「委员会读整袋陈述」为主 UI |
| 院系评袋 | **中** | `department-review` 偏**档案记录/任务审核**；与清华「教学委员会对袋作态度能力判定」粒度不同 |
| 青年教师建立指导 | **中** | onboarding=认识产品；**弱**院系沙龙式「如何写袋」内容运营 |
| 过程/展示/评估三类 | **中** | 评估场景清晰；展示/分享/同行评论（北大）**弱** |
| 系统汇数成雏形 | **高** | 采集、AI、完整度、集成中心方向一致（北大平台思路） |
| 破五唯 / 教学第一责任 | **产品可支撑** | 制度话术不在 SaaS 内强制；租户可配模板与职称条件 |
| 与 OBE 质量评价一体 | **刻意拆分** | 清北校内常同属教学质量/教发体系；本产品 **quality 菜单分页** 与 portfolio **分域**（正确隔离 tenant SaaS，但教师心智上需文案解释「袋 ≠ 达成度报告」） |
| 反堆砌 | **张力** | 完整度 % 与五框架易导向「填满」；需用场景门禁与代表作视图对冲 |

## 4. 内容结构对照

### 4.1 清华六模块 ↔ 现网落点

| 清华模块 | 现网大致落点 | 缺口 |
|----------|--------------|------|
| 教学简历 | `teacher-profile`、身份标签、名册字段 | 缺统一「教学简历」呈现面（时间线/代表作首页） |
| 教学数据 | 讲授课程、完整度、可能集成成绩/工作量 | 缺「教学数据库」一等模块名与刚性数据仪表（工作量/成绩/学评聚合视图） |
| 教学陈述 | `teacher-philosophy` | 有；需强化与数据/过程记录的**对照阅读**（评袋视图） |
| 教学过程记录 | 课程档案材料、拓展、评价页 | **最弱**：课前准备/课堂过程/课后反馈的结构化连续记录不足 |
| 教学发展与研究（可选） | 拓展活动、发展档案/培训类 admin、政策库 | 有碎片；缺「发展」聚合 |
| 教学成果与奖励（可选） | `teacher-honor`、国赛/成果类 admin | 相对齐 |

### 4.2 北大四维 ↔ 现网

| 北大维度 | 现网 | 缺口 |
|----------|------|------|
| 教学基本信息 | 资料+课程档案+理念 | 大纲/课件体系化因租户模板而异 |
| 教学成果 | 荣誉、部分成果库 | 慕课/录像等多媒体展示弱于经典 ePortfolio |
| 教学发展 | 拓展/培训/双高任务等 | 教发活动过程数据自动入库弱（北大强调平台汇数） |
| 教学评价 | evaluation 页、审核 | 学评/同行评价作为袋内证据的标准化导入因租户而异 |

## 5. 交互与组织差异（含已定入口 IA）

| 点 | 清北心智 | 现网/远景 |
|----|----------|-----------|
| 教师入口 | 建袋、写袋、改袋 | **我的工作台**待办驱动（正确办事）；应叠加「我的教学代表作」阅读面 |
| 管理员 | 少见「顶栏代填」主叙事 | 名册进入代维护（`PORTFOLIO_ENTRY_IA_08`）；勿顶栏 Select 当主入口 |
| 院系 | 委员会**评袋** | 审核台**审材料任务** + 职称院审；评袋视图待补 |
| 成功标准 | 凝练、可晋升答辩、成长可见 | 完整度、待办清零、场景包通过 —— **指标需与代表作质量解耦宣传** |

## 6. 产品建议（仅审查优先级 · 未改码）

| 优先级 | 建议 | 对齐 |
|--------|------|------|
| **P0 语言** | 工作台副文案：「维护教学代表作 / 证据」；禁工作壳黑话 | 清华隐喻 |
| **P0 入口** | 名册进入 + 本人直达（已定） | 教师主体 |
| **P1 代表作视图** | 只读「整袋预览」：理念 + 数据摘要 + 关键证据 + 过程记录摘录，供院审/晋升读 | 评袋/展示 |
| **P1 过程记录** | 课程维度轻量「课次/阶段反思」或过程类目模板（租户可配） | 全过程 |
| **P1 反堆砌** | 场景出包强调「甄选」；完整度旁提示「代表作≠填满」 | 北大/清华质量观 |
| **P2 三类用途** | 产品说明：日常维护 / 展示导出 / 评估场景 三出口同一底座 | 北大三类 |
| **P2 青年建立** | onboarding 增加「写什么」内容卡，非仅产品导览 | 青年重点 |
| **不做** | 为对齐清北合并 quality 与 portfolio 域；不做营销 ePortfolio 社区优先 | SaaS 边界 |

## 7. 三 Skill 摘要

| Skill | 结论 |
|-------|------|
| **Impeccable** | 主路径应同时回答「缺什么证据」与「我的教学故事是否可读」；评袋/晋升读侧缺代表作面 |
| **Finesse** | 完整度 KPI 可保留但勿压过叙事；代表作预览用单栏章节非 KPI 墙 |
| **Taste** | 高校信任场景：体检/代表作，不是 CRM 填表；禁「域/壳」与刷完整度游戏感 |

## 10. 须补充规格（认可清北后 · 产品合同草案）

> 原则：**在现网证据底座上叠加清北阅读/过程/评袋层**，不推倒重来；不与 `/quality` 合并；不引入「换域/工作壳」文案。

### 10.0 目标心智（改完后用户应感到）

| 角色 | 应感到 |
|------|--------|
| 教师 | 「我在打磨**教学代表作**」+「缺什么证据一眼清」；不是只刷完整度 |
| 院系 | 「既能审材料任务，也能**通读整袋**给晋升/评议意见」 |
| 管理员 | 名册进入代维护；配置模板/清单映射；不顶栏当主入口 |

### 10.1 S1 · 教学代表作只读预览（P0）

| 项 | 规格 |
|----|------|
| **目的** | 对齐清华「代表作/可被委员会阅读」；对齐北大「有目标甄选后的可读整体」 |
| **入口** | 教师：工作台主 CTA 旁「预览我的代表作」；档案页顶「预览」；院审/职称：任务或申请上「读整袋」 |
| **形态** | 单栏长文+锚点目录（非 KPI 墙）；顶条：教师姓名 · 院系 · 生成时间 · 用途标签（日常/晋升包） |
| **章节顺序（默认映射清华六模块）** | ① 教学简历摘要 ② 教学数据摘要 ③ 教学陈述（理念全文/摘要） ④ 过程记录精选 ⑤ 发展（可选） ⑥ 成果与奖励（可选） · 末附「证据清单（已甄选）」 |
| **数据** | 只读聚合现有 API：profile / philosophy / completeness+讲授 / honor / course-archive 精选 official 记录 / 过程记录（S3）；**禁止**为预览另造第二套编辑模型 |
| **甄选** | 每模块最多 N 条精选（租户可配）；未甄选时显示「尚未甄选 · 去档案挑选」钉条，不整页大 Empty |
| **AI** | 可生成「导读摘要」草稿，须标注建议核验；不可自动写正式陈述顶替教师 |
| **禁** | 预览里再嵌第二套选人；预览当编辑器；完整度六环装饰替代章节 |

**现网落点候选：** 新路由如 `/portfolio/teacher/masterpiece`（名待批）或 `teacher-archive` 上只读模式 + `?view=masterpiece`；院审从 `department-review` / 职称院审钻取。

### 10.2 S2 · 六模块清单导航（P0）

| 项 | 规格 |
|----|------|
| **目的** | 把散落页面收成清北可读结构，**不**再加菜单超市 |
| **形态** | 工作台或「我的档案」内 **清单轨**（6 块）：状态=未启/草稿/可评/已用于场景；点击进**已有页** |
| **映射表（默认）** | 见下表；租户模板可改 label，不可改「必选四 + 可选二」语义除非租户关闭可选 |
| **与完整度关系** | 清单状态 ≠ 完整度% 简单拷贝；完整度可作模块内进度，清单看「是否具备代表作章节」 |

| 清华模块 | 现网路由/能力 | 清单 CTA |
|----------|---------------|----------|
| 教学简历 | `teacher-profile` + 身份摘要 | 维护资料 |
| 教学数据 | workbenchSummary / 讲授课程 / 完整度仪表 | 查看数据摘要 |
| 教学陈述 | `teacher-philosophy` | 撰写/修订理念 |
| 教学过程记录 | **S3 新能力** + 课程档案过程类 | 记一课/一阶段 |
| 教学发展与研究 | extension / 培训发展类 | 维护发展 |
| 教学成果与奖励 | `teacher-honor` 等 | 维护成果 |

**禁：** 再做一个与侧栏重复的 20 项功能叶；用 StageRail 串全站质量域。

### 10.3 S3 · 全过程过程记录（P1）

| 项 | 规格 |
|----|------|
| **目的** | 清华全过程：课前准备 · 过程 · 结果反馈；梁思思式「课后短反思」 |
| **最小闭环** | 教师选课程（讲授真源）→ 新建「课次/阶段记录」→ 三段字段（准备/过程/反馈）或租户模板字段 → 保存为档案记录（official 前可草稿）→ 可精选进代表作 |
| **频率** | 产品鼓励「短、勤」；列表按课程时间倒序；工作台可出「本周未记过程」轻待办（可 dismiss） |
| **与课程档案** | 五框架仍管材料槽；过程记录是**时间序列叙事**，可双向链接材料 |
| **院审** | 过程记录可进材料审核；评袋时在代表作第④章展示精选 |
| **禁** | 强制每日打卡游戏化；无课程锚点的空日志 |
