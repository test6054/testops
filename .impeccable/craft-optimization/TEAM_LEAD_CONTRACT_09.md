# 09 本场带队 · 前后端交互合同（源码裁决）

> 2026-07-16 · 手读 edu-mark + mark-vue · **未改业务码**  
> 目的：把「主考带一部分老师完成任务」落到**真实权限与 API**，禁止空想「派给某人 / 催办」字段。

---

## 0. 一句话

| 环节 | 真实带队方式 | 禁止脑补 |
|------|--------------|----------|
| **扫描** | 有权限的人清**共享异常队列**；主考看运营概览与异常数 | 异常单「指派给王老师 / 催办」API（响应无 assignee） |
| **阅卷** | 主考配**题组+教师+分配策略** → 任务写入 reviewer → 教师**任务池领取/批阅** | 管理员代主考做分配；实时「催办」消息字段 |
| **学情** | 锁考后本场分析（讲评/题质量） | 超管 OCR 配置进本场工作台 |

## 1. 角色与权限（edu-mark）

### 1.1 主考老师 = 考试创建人

真源：`ExamMarkPermissionService`

| 方法 | 规则 |
|------|------|
| `requireExamOwnerPermission` | **仅** `userId == exam.createUser`；**无任何管理员豁免** |
| 适用 | 分配策略、解匿名等「代主考不可」写操作 |
| `isExamOwner` | 判断是否主考 |
| `requireExamMarkReadPermission` | 主考 **或** 已在阅卷组织内的评阅教师可读；超管全租户读仅读不写 |
| 主考补成员 | `MarkingOrganizationChiefExaminerMembershipRepairService`：主考访问主链时若未在题组则**补入首个题组**为评阅人 |

**产品语言：** 主考 = 本场考试负责人（创建人），不是「工作壳」。

### 1.2 协作教师 = 题组评阅人

- 组织读：`countExamMarkReviewerAssignments > 0` 或主考。  
- 写分/领取：任务 `reviewerUserId` / claim 上下文为权限锚点（见 `MarkingOrganizationService` 注释）。  
- 维护名册：主考或组织内已分配评阅教师（非班主任猜权限）。

### 1.3 超管 / 租户管理员

- 超管：列表可读全租户，**不能** `requireExamOwnerPermission` 写分配。  
- 租户管理员（SCH_TECH）：须走考试主考/评阅分配既有链，**不得**绕过考试级写边界。  
- OCR 渠道等：配置域，**不进 09 本场带队合同**。

## 2. 扫描带队合同

### 2.1 页面 / API 真源

| 能力 | 前端 | 后端（代表） |
|------|------|----------------|
| 本场扫描运营壳 | `exam-scan-ops` → `ScanOpsWorkbench domain=exam` | `ExamScanOpsController` |
| 异常/重复待办 | `scan-live-monitor` · `ScanExceptionPanel` | `listScanAttentions` 等；`ExamWorkbenchScanMonitorPanelResponse` |
| 身份绑定 | monitor 内 batch bind | `ExamMarkController.batchBindPapers` · `ExamPaperBindingService` |
| 工单入站 | kiosk / work-order | `ScanWorkOrderController`（设备 ingress，**不是**人派任务单） |

### 2.2 `ScanAttentionItemResponse` 有什么 / 没有什么

**有：** attentionType、source、examId、scanBatchId、paperInstanceId、candidate/student、诊断与状态类字段。  

**无：** `assigneeUserId` / 指派人 / 催办截止。  

→ 带队形态 = **共享队列协作清障**，不是工单系统「派单给人」。

### 2.3 角色可见动作（合同）

| 角色 | 知况 | 可做 | 不做 |
|------|------|------|------|
| 主考 | 应扫/已扫类概览、异常条数、批次状态 | 进扫描运营/监控；处理异常、绑定、废弃批次（主考权限接口） | 虚构「派给李工」 |
| 有扫描权限的协作教师 | 同场异常队列 + 本场进度（若接口返回） | 办理异常、人工匹配、补扫入口 | 改分配策略、代主考配置 |
| 仅评阅教师 | 可能只见批阅程 | 不进扫描写 | — |

### 2.4 UI 文案（产品）

- 主 CTA：**处理扫描异常** / **打开监控** / **绑定考生**  
- 次 CTA：进入批次、人工录入  
- 禁：派给某某、催办扫描员（无后端字段前禁止画死）

## 3. 阅卷带队合同

### 3.1 页面 / API 真源

| 能力 | 路径 | 说明 |
|------|------|------|
| 组织详情 | `/api/mark/organization/detail` 等 | `MarkingOrganizationController` |
| 题组+教师 | `/group/save` | 题目小组含教师分配 |
| 分配/回收策略 | `/policy/allocation/save` · `/policy/recycle/save` | **主考写** |
| 派发算法 | `AllocationPlanCalculator` | 切片 → `reviewerUserId`（轮询/随机/按题/按班…） |
| 题组进度 | `MarkingOrganizationGroupTaskProgressItemResponse` | **题组级** total / finalized，非每人一行必有独立 VO |
| 试评/正评 | trial/* · formal/* | 会话就绪度、启动、完成 |
| 教师任务池 | `marking-task-pool` | claim-context + 领取任务 |

### 3.2 主考带队真实步骤（业务）

1. 创建/维护阅卷组织  
2. 建题组并加入阅卷教师  
3. 配置分配策略（及回收策略）  
4. 启动试评 → 校准 → 正评  
5. 看题组进度（已定稿/总数）  
6. 教师侧：任务池选会话/题组 → 领取 → 批阅  

### 3.3 角色可见动作（合同）

| 角色 | 知况 | 可做 | 硬约束 |
|------|------|------|--------|
| 主考 | 题组数、策略、会话状态、题组进度 | 配组/人/策略、启停会话 | 仅 createUser；管理员不可代做分配 |
| 阅卷教师 | 本人待领/进行中任务摘要 | 领取、批阅、提交 | 权限锚在 task/claim |
| 题组长（若数据有） | 本组成员与进度（以实现字段为准） | 以实现为准 | 不得发明无源码角色 |

### 3.4 UI 文案（产品）

- 主考：**配置阅卷老师与题组** · **分配策略** · **启动正评** · **查看题组进度**  
- 教师：**进入任务池领取** · **继续批阅**  
- 禁：无 API 的「催办李四」按钮当主路径（可后续接消息中心，须新合同）

## 4. 本场学情合同（简述）

- 入口：考试工作台内 AI/题目分析（锁考本场）。  
- 交付：薄弱题、关注学生、是否建议题质量复核。  
- 禁：跨考/校级超市默认；超管 OCR 配置。
