## 二、P0 — 必须修复（功能/可用性阻断）

### P0-1 建议横幅无差别覆盖，信噪比归零

**现象**："建议优先处理「模板制卷」" 横幅在 17/19 页面出现，包括 score/release（成绩发布）、archive/package（归档）等已远离准备阶段的页面。

**问题**：
- 横幅占据首屏垂直空间（约 40–48px），在所有页面都推低主内容区
- 用户在成绩发布页看到"建议处理模板制卷"会困惑——此时考试早已完成扫描和阅卷
- 横幅成为视觉噪音：当一条建议到处出现，等于没有建议

**建议**：
- 横幅应仅在 **当前阶段及前序阶段** 显示；一旦用户进入 marking/score/archive，该横幅应自动消失
- 或者改为 Toast / 一次性通知，不持久占位

**影响页面**：除 paper-template 和 answer-sheet 外的全部 17 页

### P0-2 批阅沉浸页 768px 不可用

**现象**：768px 下 marking/task/1 沉浸批阅界面在窄屏上仍尝试渲染，给分面板和影像区域严重挤压。

**问题**：
- 批阅沉浸需要同时看影像 + 给分面板 + 队列信息，768px 物理上无法承载
- SKILL 已明确：「移动端批阅沉浸可提示请使用桌面端」

**建议**：
- 768px 及以下直接展示「请使用桌面端（≥1024px）进行批阅」的引导页
- 提供返回任务池的入口

## 三、P1 — 高优改进（质感/效率显著提升）

### P1-1 空态页面缺少业务引导

**现象**：多个页面标记 `emptyStates: true`：

| 页面 | 表区域数 |
|------|----------|
| scan/batches（录入与批次） | 9 |
| scan/monitor（扫描监控） | 3 |
| scan/ledger（影像账本） | 3 |
| trial/task-pool（试评任务池） | 3 |
| marking/task-pool（阅卷任务池） | 3 |
| marking/arbitration（仲裁裁定） | 6 |
| marking/quality（抽检处理） | 3 |
| archive/package（归档列表） | 3 |

**问题**：空态区域使用基础空白或裸「暂无数据」，没有用 `UiEmpty` 提供业务引导文案。Visual Quality Bar §5：「裸暂无数据或裸 spinner 是页面只做了一半的标志」。

**建议**：
- 每个空态使用 `UiEmpty` 并带场景化文案，例如：
  - 扫描批次空 → "尚未创建扫描批次，点击「创建扫描批次」开始录入"
  - 任务池空 → "当前无待处理任务，所有试卷已完成评阅"
  - 仲裁空 → "无需仲裁的试卷，评分一致性良好"
  - 归档空 → "尚无归档包，考试结束后可创建电子归档"
- 空态中包含主操作按钮

### P1-2 scan/batches 表格过密（9 个表区域）

**现象**：录入与批次页在 1440px 下有 9 个 table 区域，是全站最复杂的页面。1024px 下更为拥挤。

**问题**：
- 9 个表区域未见明确分组标题和组间间距，形成「表格墙」
- 违反 Visual Quality Bar §4 密度张弛：「视线需要一个低密度入口再进入密集表格」

**建议**：
- 按业务分组（「录入管理」/「批次管理」/「异常处理」），组间用 `--dp-space-6`(24px) + 分节标题
- 首屏先展示 SignalBand 汇总 KPI（总录入量/异常数/完成率），再进入各分表
- 考虑用 Tabs 或折叠面板收敛不常用的表区域

### P1-3 768px 下表格列挤压严重

**现象**：768px 视口下 scan/batches、marking-org、task-pool、review-batch 等页面表格列严重挤压。

**问题**：
- 表格在 768px 下没有切换为卡片列表或简化列模式
- 操作列多按钮挤在一起，触控目标过小
- SKILL 交互规则 §4：「移动端 `TabBar` + 简化表」

**建议**：
- 768px 下隐藏低优先级列（创建时间、操作人），仅保留关键列 + 操作
- 或切换为卡片列表模式
- 操作列改为「更多」下拉菜单，保证触控目标 ≥44px

### P1-4 ContextBar label-value 对齐不一致

**现象**：跨页面对比 ContextBar，部分页面用冒号分隔 `label：value`，部分用 `·` 分隔或自由文本混排。

**问题**：Visual Quality Bar §3：「ContextBar 的 label-value 元信息行，数值列对齐或统一用 `·` 分隔」。

**建议**：
- 统一为 `·` 分隔或统一为 label-value 对齐列布局
- 全部 ContextBar 实例做一次对齐扫描

## 四、P2 — 中优改进（质感打磨）

### P2-1 阶段轨视觉权重过高

**现象**：`MarkExamStageRail` 9 个阶段全部可见，当前/完成/未开始 3 种状态色同时在屏。

**问题**：Visual Quality Bar §5：「考试九阶段轨尤其忌讳每阶段一色。一屏 tone 色超过约 4 种就要收敛。」

**建议**：
- 非当前阶段收敛为更弱的视觉层级（更小字号、更浅灰色）
- 已完成阶段用 ✓ 图标 + 灰色文字，不用绿色填充
- 当前阶段用字重 600 + 主色左边框，不用背景填充

### P2-2 marking 子页面层级模糊

**现象**：review-batch（批量复核确认）与 review（OCR/AI 复核）两个页面视觉层级几乎相同——都是 ContextBar + 表格，缺少主从关系。同样 score/summary 与 score/release 结构高度相似。

**问题**：Visual Quality Bar §1：「每屏一个主焦点」——结构相同的关联页面让用户难以快速区分意图。

**建议**：
- review-batch 列表页突出批次卡片/摘要信息，表格退为次要
- review 详情页用 ContextBar 强化「当前批次」上下文
- score/release 页面的主操作区（发布按钮）应有更突出的视觉权重
- 可在 SignalBand 中增加「发布状态」KPI，用 tone 色区分

### P2-3 1024px 侧栏与主区比例失调

**现象**：1024px 下侧栏仍保持 259px 宽度，主区仅剩约 765px。

**问题**：侧栏占比从 1440px 的 18% 上升到 1024px 的 25%，主区可用空间骤降，表格和表单开始挤压。

**建议**：
- 1024px 下侧栏收窄至 200–220px，或改为可折叠的图标侧栏
- 阶段轨在窄侧栏模式下改为图标 + tooltip 展示

### P2-4 表格数字列未右对齐

**问题**：Visual Quality Bar §6：「表格数字右对齐，单位用次级色/小字弱化，先读量级。」

**建议**：
- 所有数值列统一 `text-align: right`
- 单位（分、份、%）用 `--dp-text-tertiary` 弱化

### P2-5 SignalBand KPI 卡等高预留不足

**问题**：Visual Quality Bar §3：「KPI 等宽等高：不因数字位数不同而让某张卡变高。」测试数据数值均较小，生产数据可能暴露不等高。

**建议**：
- SignalBand 组件设置 `min-height`，预留 4 位数字高度
- 数值区域固定行高，不由内容撑开

## 五、P3 — 低优建议（锦上添花）

### P3-1 批阅沉浸 1024px 可优化队列面板

批阅沉浸在 1024px 下可用但影像区域偏窄，可考虑队列面板改为顶部横向滚动条或折叠面板，将更多宽度让给影像。

### P3-2 marking 旅程侧栏 8 项可收敛

批阅旅程（mark）侧栏有 8 个子组（试评/试评校准/正评/待批/进行中/质控/待批/进行中），信息丰富但层级较深，可考虑二级折叠或仅展示有待办的组。

### P3-3 归档域侧栏子组名重复

归档侧栏子组：「归档 · 归档 · 质量评价」——第一个「归档」是域标签，第二个是实际菜单项，文案重复。建议改为「归档管理 · 质量评价」或收敛为一级。

### P3-4 旅程轨点击流起点标签不一致

旅程轨 6 个点击步骤中，第一步标签为「创建与准备」落地到 /prep（准备工作台），但 overview 页面标签为「考试概览」。建议轨的起点也包含 overview 入口，或将 overview 并入 prep 作为首页。

## 八、改进优先级汇总

| 优先级 | 数量 | 工作量预估 |
|--------|------|------------|
| P0 必须修 | 2 | 2–3 天 |
| P1 高优 | 4 | 3–5 天 |
| P2 中优 | 5 | 3–4 天 |
| P3 低优 | 4 | 1–2 天 |
| **合计** | **15** | **约 9–14 天** |

### 建议执行顺序

1. **第一轮（P0）**：修复建议横幅阶段过滤 + 768px 批阅沉浸降级
2. **第二轮（P1）**：空态 `UiEmpty` 全站补齐 → scan/batches 分组 → 768px 表格简化 → ContextBar 对齐
3. **第三轮（P2）**：阶段轨视觉收敛 → 同级页面层级区分 → 1024px 侧栏自适应 → 数字右对齐 → KPI 等高
4. **第四轮（P3）**：沉浸模式 1024 优化 → 侧栏收敛 → 文案去重 → 旅程轨入口
